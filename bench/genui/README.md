# GistUI on generative-ui-bench

The benchmark behind [openui.com/benchmarks](https://www.openui.com/benchmarks): 70 components, 46 briefs, 4 repeats per brief. OpenUI Lang, Google A2UI and Vercel json-render are each scored by their own SDK, with one shared definition of a complete screen. This folder adds GistUI as a fourth format, using the same catalog, the same two worked examples, the same rules and the same completeness checks.

```bash
bun run bench:genui:setup     # clone the bench at the pinned commit into bench/.cache, npm install
bun run bench:genui           # key-free comparison → bench/results/genui.md + genui.json

# Live generations (API key needed), then score next to the committed runs of the same model.
# The label must be the bench's label for that exact model (gemini37 = google/gemini-3.7-flash,
# gemini = google/gemini-3.6-flash; see the bench README), or the comparison mixes models.
BENCH_MODEL=google/gemini-3.7-flash BENCH_LABEL=gemini37 OPENROUTER_API_KEY=… bun run bench:genui:run
bun run bench:genui:score gemini37
```

| File | What it does |
|---|---|
| `catalog.ts` | The 70-component catalog as a GistUI library. Child types and groups are read from OpenUI's generated signatures. |
| `prompt.ts` | The GistUI system prompt, generated by `@gistui/core`. It uses the bench's two examples (transcoded) and the same per-group usage notes OpenUI's prompt shows. |
| `validator.ts` | The bench's completeness rules and error classes, on the GistUI parser. |
| `transcode.ts` | OpenUI Lang → GistUI for the same components, statement by statement. |
| `compare.ts` | Measures prompt tokens, output tokens, cost, validity and parse speed on the committed raws of the six headline models. |
| `run.ts` / `score.ts` | Live runs, with the bench's exact request settings. |

## How GistUI writes the same screens

These are signatures and idioms only. The components and the rendered tree are the bench's.

- **Signatures:**
  - Required props are positional.
  - On components without children, optional text props may follow positionally, like `CardHeader("Title", "Subtitle")`.
  - A component's list of child components becomes its variadic children: `Card(a, b)`.
- **Inline parts:** only sections get a statement. Small parts are written where they are used: `Buttons(Button("Save"), Button("Cancel", tertiary))`.
- **Pipe tables:**
  - `Table(rows)` expands to one `Col` per column.
  - `BarChart(sales)` expands to labels plus one `Series` per column.
  - `PieChart(mix)` expands to labels and values.
  - This uses the core `ComponentSpec.table` mapping, with no change to the components.
- **Plain strings:** a string child is a `TextContent`.
- **Bare enum values:** `Tag("Live", success)`. A statement with the same name wins, so `row` stays a reference when `row = …` exists.

`GISTUI_BENCH_STYLE=deep` is an experimental prompt that also inlines containers. Only root's sections keep a statement, which saves about 5% more output. Use it for A/B live runs.

## Caveats

- **Transcoded, not generated.** GistUI's output tokens and validity in `genui.md` come from converting each OpenUI output. They show what the syntax costs for the same screen, not what a model would write. Live runs settle validity.
- **The fixed catalog has no GistUI idioms.** It has no pipe tables, composites (`Stats`) or Markdown text children, so the output-token comparison is conservative.
- **Scoring differs from the site.** The committed verdicts are scored by lang-core 0.2.16, which checks prop types. The site's figures come from earlier scoring.
